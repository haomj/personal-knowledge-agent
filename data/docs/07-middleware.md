# Middleware：Agent 的横切逻辑

Middleware 用来处理横切关注点，例如日志、权限、重试、超时和人工审批。它不应该替代业务节点，而是包裹模型调用或工具调用。

## 常见钩子

- `before_model`：模型调用前执行，可以修改消息或直接短路。
- `after_model`：模型调用后执行，可以检查输出。
- `wrap_model_call`：包裹整个模型调用，适合计时、重试、缓存。
- `wrap_tool_call`：包裹工具调用，适合权限检查、审计、异常处理。

## Logging Middleware

记录：

- 模型名称和调用时间；
- 输入消息数量；
- 输出 token 数；
- 工具名称、参数和耗时；
- 错误信息和堆栈。

日志中不要记录 API Key、完整用户隐私数据或工具返回的敏感内容。

## Permission Middleware

检查：

- 当前用户是否允许调用该工具；
- 工具是否属于高风险操作；
- 是否需要人工审批；
- 参数是否超出允许范围。

权限检查要放在工具执行之前，不能只依赖模型的自觉。

## Retry Middleware

只对可安全重试的操作自动重试：

- 知识检索、只读查询可以重试；
- 保存报告、发送邮件、扣款等有副作用的操作不能盲目重试。

重试要设置最大次数、超时和退避策略。对于有副作用的操作，需要幂等键或人工确认。

## 执行顺序

多个 Middleware 同时存在时，顺序会影响结果。通常：

1. 日志/追踪在最外层，记录完整调用；
2. 权限检查在工具执行前；
3. 重试包裹实际调用；
4. 业务逻辑在最内层。

需要通过日志或测试确认实际顺序，而不是凭假设。
